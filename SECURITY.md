# Security Policy

Security and safety reports are welcome within SushiGPT's [contribution policy](docs/contributing.md).

## SushiGPT-specific vulnerabilities

This repository currently has no documented private reporting channel for fork-specific vulnerabilities, and GitHub private vulnerability reporting is not enabled. Do not disclose vulnerability details in public issues or pull requests. A private reporting channel needs to be established before such details can be submitted to the fork's maintainers.

Non-sensitive safety concerns may be discussed in the repository's issue tracker.

## Vulnerabilities affecting upstream OpenAI Codex

The inherited OpenAI reporting channel is the [OpenAI Bugcrowd program](https://bugcrowd.com/engagements/openai). Follow its current scope and vulnerability disclosure guidelines when reporting an issue affecting upstream Codex. This channel does not establish coverage for SushiGPT-specific changes.

## Operating Codex safely

For details on Codex security boundaries, including sandboxing, approvals, and network controls, see [Agent approvals & security](https://developers.openai.com/codex/agent-approvals-security).
